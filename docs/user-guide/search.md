# 搜索

侧边栏顶部的搜索框，同时搜索**页面标题**和**块正文**。

---

## 基本行为

- 输入内容后 **250ms 防抖**才发起查询（`packages/renderer/src/components/Sidebar.tsx:82`）。
- 查询走 IPC 到主进程，直接对 SQLite 执行 `LIKE` 匹配。
- 结果按**最近更新**排序。
- 点任意结果跳到对应页面，并清空搜索框、收起结果面板。
- 点搜索框外部收起结果面板。
- 查询出错时显示"没有找到匹配的结果"，不弹错误。

---

## 匹配范围

| 目标 | 匹配字段 | 说明 |
| --- | --- | --- |
| 页面 | `pages.title` | 标题为空时按"无标题"展示 |
| 块 | `blocks.content` 的 `$.text` | 只匹配块的**文本字段** |

### 哪些块能被搜到

| 块类型 | 可搜索 | 原因 |
| --- | --- | --- |
| 正文、标题、列表、待办、引用、代码 | ✅ | 有 `text` |
| **表格** | ✅ | 写入时同步生成纯文本摘要 |
| 分割线 | ❌ | 无文本 |
| 图片 | ❌ | 无文本 |

表格的摘要格式是每行用 ` | ` 连接、换行分隔：

```
块类型 | 说明
文本 | 段落、标题、列表、待办
```

因此搜"说明"能命中表格里的内容。

---

## 命中上限

查询分别对页面和块设了上限：

| 目标 | 上限 | 排序 |
| --- | --- | --- |
| 页面 | 20 条 | `updated_at DESC` |
| 块 | 30 条 | `updated_at DESC` |

**两类结果合并返回**，所以一次搜索最多 50 条结果。超过上限时不是"完全搜不到"，
而是"只展示最近的 N 条"——被截断的通常是更久没更新的内容。

---

## 结果展示

- **标题命中**：显示页面图标 + 页面标题，副标题是标题本身。
- **正文命中**：显示页面图标 + 页面标题，下方缩进一行是**内容片段**。

片段的生成规则（`src/main/db.ts:416`）：

```
命中位置 = 首次出现位置（忽略大小写）
起点     = max(0, 命中位置 - 20)
片段     = 文本[起点, 起点+60]
```

- 片段前面被截断时加 `…`，后面被截断时也加 `…`。
- 片段最多 60 个字符。

---

## 匹配语义

使用 SQL `LIKE '%关键词%'`，因此：

- **子串匹配**：`note` 能命中 `notion`。
- **默认不区分大小写**（SQLite `LIKE` 对 ASCII 不敏感）。
- **不支持**多个关键词的 AND 组合、也不支持字段限定语法。
- 特殊字符 `%` 和 `_` 在 `LIKE` 中是通配符，未做转义——搜索 `%` 会匹配所有内容。

> 如需改进，建议在 `src/main/db.ts:384` 的 `search()` 里对查询串做转义。

---

## 性能

- 搜索直接在 SQLite 上跑，命中上限（20 + 30）保证单次查询开销可控。
- 页面标题和块正文**没有建全文索引**，只有 `blocks(page_id, position)` 和
  `pages(parent_id, position)` 两个 B-tree 索引。数据量很大时搜索会变慢，
  届时可考虑引入 FTS5 虚拟表。
