# AI 排障

按症状定位。所有错误信息都可以直接在界面上看到原文。

---

## 「没有检测到可用模型」

设置 → AI 助手 → 模型列表为空，或显示红色提示。

### 原因

模型列表来自本机 `~/.pi/agent` 的配置。**没有配置过凭据**就没有模型可选。

### 排查步骤

**1. 确认凭据文件存在**

```bash
cat ~/.pi/agent/auth.json
```

文件应该包含对应 provider 的密钥。**不要**把这个文件的内容贴到任何地方。

**2. 确认磁盘有空间**

```bash
df -h ~
```

Pi 的运行时快照是在创建时刷新的，磁盘满会导致刷新静默失败，
模型列表就是空的。

**3. 清理孤儿锁（最常见的隐形原因）**

Pi 用一个**空目录** `~/.pi/agent/auth.json.lock` 做锁。
如果之前应用异常退出（崩溃 / `kill -9` / 强制退出），
这个空目录会留下，**导致之后每一次认证读取都失败**。

```bash
ls -la ~/.pi/agent/auth.json.lock
```

如果它是一个**空目录**，且 mtime 超过 60 秒，直接删掉：

```bash
rmdir ~/.pi/agent/auth.json.lock
```

> 应用启动时也会自动清理这种锁（只清理"空目录 + 超过 60 秒未更新"的，
> 见 [Pi SDK 集成](integration.md#孤儿锁清理)）。
> 但如果锁很新（说明有活进程持有），**不要**手动删。

**4. 点「刷新」**

设置里点「刷新」按钮重新读取模型列表。运行时快照为空时会强制刷新一次。

**5. 还没好？重置对话**

AI 面板里点「重试」，或设置里点「重置对话」。
会话可能是在环境异常时建立的，丢掉重建。

## 「提供商「X」没有可用凭据」

调用模型时抛的 `No API key for provider: X` 被本地化后的提示。

### 原因

选了 `provider/id`，但这个 provider 在 `~/.pi/agent/auth.json` 里没有密钥。
`resolveModel()` 会在选择阶段过滤掉没凭据的 provider，
但如果选模型时凭据还在、之后被删了，就会出现这种情况。

### 处理

在设置里换一个有凭据的模型，或给 pi 补上该 provider 的密钥。

## 「没有检测到可用模型(原因)」/ 初始化失败

AI 面板顶部出现红色错误条。

主进程在会话初始化时做了**提前拦截**：

```ts
if (modelRuntime.getAvailableSnapshot().length === 0) {
  const detail = modelRuntime.getError()
  throw new Error(
    `没有检测到可用模型${detail ? `(${detail})` : ''}。` +
      '请确认本机 pi 的凭据有效(~/.pi/agent/auth.json),并确保磁盘有可用空间。'
  )
}
```

**在调用模型之前就报错**，比让模型调用阶段抛 "No API key" 更可操作。

处理方式同上：检查凭据 → 清孤儿锁 → 刷新 → 重试。

## 「磁盘空间不足,操作未能写入」

原始错误是 `disk is full` / `no space left` / `ENOSPC`。

清理磁盘后重试。这个错误也会**导致模型快照刷新失败**，
进而让模型列表变空——两个症状可能同时出现。

## AI 说"我无法访问你的笔记"

### 可能原因一：上下文被关掉了

设置 → AI 助手 → 「自动附带当前页面」关闭时，AI 看不到你当前打开的页面。
它必须自己调 `notes_list_pages` + `notes_read_page` 去找。

这个行为是**提示词里明确写的**：

> - 你看不到用户当前打开的页面。要操作页面内容时,先用 notes_list_pages 找到页面,
>   再用 notes_read_page 拿到块 id,不要凭空猜测块 id。

如果 AI 没有按这个流程做，说明模型能力偏弱，可以：
- 打开「自动附带当前页面」，让上下文直接给它；
- 或者在「附加指令」里明确写"先调 notes_read_page 确认块 id 再修改"。

### 可能原因二：AI 幻觉了块 id

块 id 是 UUID，模型不可能凭空猜对。**必须**先读取页面拿到真实 id。

在「附加指令」里加一句"修改前务必先 notes_read_page"能显著降低这类错误。

## AI 改了笔记，但界面没变

### 正常情况

AI 改动的是**当前页面**时，界面立即刷新。

### 异常情况

如果 AI 改的是**别的页面**：
- 侧边栏的标题和图标**会**更新（因为 `refreshFromAi()` 重读了 pages）；
- 但那个页面的**块内容**要等切过去才刷新。

### 排查

1. 切到别的页再切回来，看是否刷新。
2. 仍不刷新 → 重启应用。

`refreshFromAi()` 只重读**当前页**的块，不会重读所有页面的块。
这是有意的优化（避免每次 AI 操作都拉全量数据）。

## 对话历史被清空了

**这是预期行为**，不是 bug。

会话用的是 `SessionManager.inMemory()`——对话历史**只在内存里**，
不写磁盘。关掉应用就没了。

以下操作会**主动重置**会话：

| 操作 | 为什么 |
| --- | --- |
| 设置里点「重置对话」 | 显式重置 |
| 修改「附加指令」 | 改变了系统提示词，旧会话不匹配 |
| 修改「自动附带当前页面」 | 同上 |
| AI 面板里的「重试」 | 显式丢弃后重建 |

**只改模型不会重置**——用 `session.setModel()` 就地切换，对话保留。
切换成功会有通知「已切换模型:provider/id」。

## 消息发出后没有反应

### 检查是不是还在流式输出

AI 面板底部有「思考中…」和转圈图标。输入框右侧变成 **■** 表示正在生成。

### 模型请求很慢

某些模型首 token 时间较长。等待或点 ■ 中断。

### 自动重试

SDK 在遇到可重试的错误时会自动重发，界面会显示通知
「请求失败,自动重试(N/M)…」。

## 工具调用失败了

工具徽标显示红色叉号。常见的是"实体不存在"：

- `块不存在: <id>` —— 模型用了过期的块 id（页面内容已被改动或删除）。
- `页面不存在: <id>` —— 同理。

这是**可预期的业务错误**，工具返回的是错误结果而不是崩溃，
模型会读到错误并重新尝试。

如果模型反复用无效 id，在「附加指令」里加
"任何修改前必须先 notes_read_page 获取最新块 id"。

## AI 改了表格，结果格式不对

表格的 `table` 参数是**二维字符串数组**，第一行作表头。

模型传了不规则的数组时会被**自动规范化**：列数取最大值，短行用空字符串补齐。
所以不会因为模型传了参差不齐的数组而报错——但补出来的空单元格可能不符合预期。

`notes_update_block` 传 `table` 是**整表替换**，不是合并。
如果模型只想改一个单元格，它应该先 `notes_read_page` 读出整表，改完再整体传回。

## 排查信息收集

需要反馈问题时，附上这些信息：

1. **设置 → 关于**里的 Electron / Node / 平台版本。
2. AI 面板显示的**错误原文**（点「重试」前先截个图）。
3. `~/.pi/agent` 下**有哪些文件**（列出文件名即可，**不要**贴 `auth.json` 的内容）。
4. 触发问题的**具体操作**。
